## 画面と状態

次の状態を設ける。

1. 出題中
2. 意味の表示・自己採点待ち
3. 回答の保存
4. 次の問題

「思い出せた」「答えを見る」のどちらでも計測を止める。その時点では成績を確定せず、自己採点を選んだ時点で履歴と集計を更新する。

同じ問題を重複保存しない。

残り3秒の表示は経過時間の表示へ変更する。時間経過による自動誤答処理は廃止する。

## 回答時間

保存単位はミリ秒とし、画面では秒に換算する。

時間の長さには単調増加時計を使い、回答日時と復習予定は日時として保存する。

初期案では単語の表示時から計測する。ただし、音声を待つ時間やボタン操作を含むため、純粋な記憶検索時間とは扱わない。

音声設定と出題方式も記録し、異なる条件の回答速度を一括で比較しない。

次の事項は未決定とする。

- 計測開始の正確なタイミング
- 別のタブやアプリへ移った場合の計測と集計の扱い

## 保存データの構成案

回答履歴、単語ごとの現在状態、日別集計、設定、データ形式のバージョンを保存する。

回答履歴は1回答につき1件とする。

| 項目 | 内容 |
|---|---|
| eventId | 回答を識別するID |
| setId / setVersion | 教材セットと版・バージョン |
| entryId | 学習項目の安定した識別子 |
| entryType | 単語・イディオム・句動詞・定型表現などの種類 |
| wordNo | 既存1900語の番号など、表示・移行用の番号 |
| answeredAt | 回答確定日時 |
| result | recalled / partial / notRecalled |
| latencyMs | 意味表示までの所要時間 |
| previousAnsweredAt | 前回の回答日時。初回は空 |
| elapsedSincePreviousMs | 前回からの経過時間。初回は空 |
| previousScheduledDue | 回答前の復習予定 |
| nextScheduledDue | 今回決まった次回復習予定 |
| presentationMode | 出題方式 |
| audioEnabled | 自動音声の利用設定 |
| isRetry | 同じ学習中の再出題か |
| sessionId | 学習回を識別するID |
| schedulerVersion | 復習計算のバージョン |

日時はタイムゾーンを含む形式で保存する。

旧データの累計と最新状態を保持し、新しい回答履歴は変更後から蓄積する。履歴開始前の累計があることを、出力時にも識別できるようにする。

保存キー、保存方式、保存量が増えた場合の扱いは実装前に確定する。

## 復習の調整

日を空けた出題での自己採点を主な根拠とする。

直後の再出題は補強学習として別扱いにし、即答したことだけで復習間隔を大きく延ばさない。

速度を使う場合は、本人の同じ出題条件の履歴と比較する。履歴が少ない間は速度による調整を弱めるか行わない。

次の事項は未決定とする。

- 現在の方式を拡張するか、FSRS等を使うか
- 初期間隔、延長・短縮の計算、上下限
- 3段階の自己採点の反映方法
- 個人に合わせた調整を始める条件
- 直後の再出題の回数と挿入位置
- 既存の復習予定を引き継ぐ方法

復習モデルは記憶状態の推定であり、忘れる日を確実に予測するものではない。

## データ出力

JSONには、次を含める。

- schemaVersion：データ形式のバージョン
- exportedAt：出力日時
- 単語ごとの状態
- 回答履歴
- 日別集計
- 設定
- 復習計算のバージョン
- 使用した教材セットの識別子・版・バージョンと項目識別子

CSVは1回答を1行とする。日本語を含むUTF-8で出力し、引用符・改行などを適切に扱う。

Safariからファイルを取り出せる操作を用意する。端末ごとの保存操作は実機で確認する。

出力は元の記録を削除しない。読み込み・復元は別機能として扱う。

## 教材ファイルの構成案

JSON形式を候補とし、アプリのコードと教材を分ける。次のパスは設計案であり、まだファイルは作成しない。

- data/sets/target1900.json：既存1900語
- data/sets/daily-conversation.json：日常会話の単語・表現
- data/sets/computer-articles.json：コンピュータ系の記事向けの単語・表現
- data/sets/index.json：利用できるセットの一覧

各セットには setId、title、version、出典情報と項目一覧を持たせる。各項目の構成案は次のとおり。

| 項目 | 内容 |
|---|---|
| entryId | 順序を変えても保持する識別子 |
| expression | 英単語または複数語の表現 |
| entryType | word / idiom / phrasalVerb / phrase |
| meaningJa | 今回学ぶ日本語の意味 |
| exampleEn / exampleJa | 短い例文と日本語訳 |
| tags | 日常会話・コンピュータ分野など |
| relatedEntryIds | 関連する語・表現。任意 |

学習記録はセットと項目の安定した識別子に結び付ける。配列の位置や画面の連番を記録の識別子にしない。

同じ綴りでも意味が違う項目の記録を自動で共有しない。複数セットに同じ意味の項目を含める場合の共有方法は未決定とする。

既存1900語の記録は旧番号との対応表で引き継ぐ。抽出時に現行の英単語・意味・番号が変わっていないことを確認する。

GitHub Pagesで教材を読み込めることを確認する。読み込みに失敗した場合は理由を表示し、既存の学習記録を消さない。HTMLを端末で直接開く方法やオフライン利用を引き続き支えるかは未決定とする。

追加教材の収録語、語数、例文、出典、セットの選択画面、項目種類の分類、複数セットでの履歴共有、教材変更時の記録の扱いは実装前に確定する。
