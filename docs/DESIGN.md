## 画面と状態

次の状態を設ける。

1. 出題中
2. 意味の表示・自己採点待ち
3. 回答の保存
4. 次の問題

「思い出せた」「答えを見る」のどちらでも計測を止める。その時点では成績を確定せず、自己採点を選んだ時点で履歴と集計を更新する。

同じ問題を重複保存しない。

残り3秒の表示は経過時間の表示へ変更する。時間経過による自動誤答処理は廃止する。

## 回答時間（初期実装）

単語を表示して計測処理を開始した時点から、意味表示ボタンを押すまでをミリ秒で保存する。自己採点の時間は含めない。時間の長さは performance.now()、回答日時と復習予定は日時を使う。

画面を離れたりブラウザーが非表示になったりした間は計測を止める。戻った後は残りの時間を加算する。中断のあった回答は timingValid=false とし、回答時間を復習の速度補助計算には使わない。

音声を待つ時間や操作時間は含むため、純粋な記憶検索時間とは扱わない。音声使用の有無、音声速度、手動再生回数も記録する。手動再生した回答の時間は速度補助計算から除外する。

## 保存データの構成案

回答履歴、単語ごとの現在状態、日別集計、設定、データ形式のバージョンを保存する。

回答履歴は1回答につき1件とする。

| 項目 | 内容 |
|---|---|
| eventId | 回答を識別するID |
| setId / setVersion | 教材セットと版・バージョン |
| entryId | 学習項目の安定した識別子 |
| entryType | 単語・イディオム・句動詞・定型表現などの種類 |
| wordNo | 既存1900語の番号など、表示・移行用の番号 |
| answeredAt | 回答確定日時 |
| result | recalled / partial / notRecalled |
| latencyMs | 意味表示までの所要時間 |
| previousAnsweredAt | 前回の回答日時。初回は空 |
| elapsedSincePreviousMs | 前回からの経過時間。初回は空 |
| previousScheduledDue | 回答前の復習予定 |
| nextScheduledDue | 今回決まった次回復習予定 |
| presentationMode | 出題方式 |
| audioEnabled | 音声使用の有無。手動再生時も記録 |
| speechRate / audioReplayCount | 音声速度と手動再生回数 |
| timingValid | 中断のない参考時間か |
| isRetry | 同じ学習中の再出題か |
| sessionId | 学習回を識別するID |
| schedulerVersion | 復習計算のバージョン |

日時はタイムゾーンを含む形式で保存する。

旧データの累計と最新状態を保持し、新しい回答履歴は変更後から蓄積する。履歴開始前の累計があることを、出力時にも識別できるようにする。

保存先は localStorage の target1900_bundle_v4 とする。状態・日別集計・設定・計画・履歴を一つのデータとして一回で書き込み、成功した後に回答を確定して次の問題へ進む。

保存失敗時は次の問題へ進まず、画面に理由の確認と再試行を案内する。履歴を自動削除しない。容量が増えた場合の保存方式の変更は将来検討する。

旧キーは移行後も保持する。以後は新しい保存キーを正本とする。JSONには履歴開始日時と旧累計を含める。壊れた保存データは自動で上書きせず、JSONで元の内容を取り出せるようにする。

## 復習の調整（初期実装）

正式なFSRSは使わず、次の簡易方式を実装する。数値は初期設定であり、科学的に最適と確定した値ではない。

- 初回の正解と誤答は約1日後に確認する。
- 曖昧な回答は前回間隔の半分を目安とし、1〜3日へ収める。
- 直後の再出題、または前回回答から12時間未満の正解では間隔を延ばさず、直前に決まった未到来の復習予定を保持する。
- 誤答・曖昧な回答後の最初の正解は約1日後に確認する。
- それ以外の正解は、前回の予定間隔と実際の経過日数の短い方を基準に約2倍へ延ばし、本人・単語の履歴で補正する。
- 計算する間隔は1〜180日、0.1日単位とする。既存の有効な復習予定は移行時に保持する。

「間隔を空けた回答」は再出題を除き、前回から12時間以上経過した回答とする。

本人の補正は直近30件の間隔を空けた回答を使い、8件以上ある場合に正解率から0.8〜1.2倍の係数を求める。履歴不足時は1倍とする。

単語の補正はその単語の直近10件の間隔を空けた回答を使い、3件以上ある場合に正解率から0.85〜1.05倍の係数を求める。履歴不足時は1倍とする。

速度の補助補正は同じ本人・同じ音声条件の、中断や手動再生のない間隔復習の正解履歴を使う。音声ありでは音声速度も一致させる。直近50件のうち5件以上あれば中央値と比べ、0.8倍未満の時間なら間隔を1.05倍、1.25倍を超える時間なら0.95倍とする。それ以外は1倍とする。速度で正誤を変えない。

誤答と曖昧な回答は数問後に最大2回まで再出題する。再出題での正解を間隔復習の連続成功として扱わない。

復習モデルは記憶状態の推定であり、忘れる日を確実に予測するものではない。

## データ出力

JSONには、次を含める。

- schemaVersion：データ形式のバージョン
- exportedAt：出力日時
- 単語ごとの状態
- 回答履歴
- 日別集計
- 設定
- 復習計算のバージョン
- 使用した教材セットの識別子・版・バージョンと項目識別子

CSVは1回答を1行とする。日本語を含むUTF-8で出力し、引用符・改行などを適切に扱う。

Safariからファイルを取り出せる操作を用意する。端末ごとの保存操作は実機で確認する。

出力は元の記録を削除しない。読み込み・復元は別機能として扱う。

## 既存1900語の分離（今回実装）

data/target1900.js に既存の1900語を移す。通常のスクリプト読み込みで利用し、教材はアプリの学習処理と独立して編集できる。読み込み失敗時は出題を止め、既存の記録を保持して再読み込みを案内する。

セット識別子は target1900、内部バージョンは legacy-1900-v1 とする。内部バージョンは出版社の版番号ではない。元リポジトリを記載し、書籍・サイト等の正確な出典と版は未確認と明記する。

既存の番号と状態キーを維持し、新しい履歴には target1900:番号 の項目識別子を保存する。1900語の英単語・意味・番号・セクションは変更しない。

## 教材セット拡張の構成案（後日検討）

JSON形式を候補とし、アプリのコードと教材を分ける。次のパスは設計案であり、まだファイルは作成しない。

- data/sets/target1900.json：既存1900語
- data/sets/daily-conversation.json：日常会話の単語・表現
- data/sets/computer-articles.json：コンピュータ系の記事向けの単語・表現
- data/sets/index.json：利用できるセットの一覧

各セットには setId、title、version、出典情報と項目一覧を持たせる。各項目の構成案は次のとおり。

| 項目 | 内容 |
|---|---|
| entryId | 順序を変えても保持する識別子 |
| expression | 英単語または複数語の表現 |
| entryType | word / idiom / phrasalVerb / phrase |
| meaningJa | 今回学ぶ日本語の意味 |
| exampleEn / exampleJa | 短い例文と日本語訳 |
| tags | 日常会話・コンピュータ分野など |
| relatedEntryIds | 関連する語・表現。任意 |

学習記録はセットと項目の安定した識別子に結び付ける。配列の位置や画面の連番を記録の識別子にしない。

同じ綴りでも意味が違う項目の記録を自動で共有しない。複数セットに同じ意味の項目を含める場合の共有方法は未決定とする。

既存1900語の記録は旧番号との対応表で引き継ぐ。抽出時に現行の英単語・意味・番号が変わっていないことを確認する。

GitHub Pagesで教材を読み込めることを確認する。読み込みに失敗した場合は理由を表示し、既存の学習記録を消さない。HTMLを端末で直接開く方法やオフライン利用を引き続き支えるかは未決定とする。

追加教材の収録語、語数、例文、出典、セットの選択画面、項目種類の分類、複数セットでの履歴共有、教材変更時の記録の扱いは実装前に確定する。

## 検証と残る事項

復習、移行、採点、計測、保存失敗、JSON・CSV出力は tests/run.cjs で検証する。DOM、保存容量エラー、ダウンロードはモック環境での確認であり、Safari実機の確認とは区別する。

Safariでの音声、実際のダウンロード、画面操作は実機で確認する必要がある。追加教材、セット選択、復元、長期履歴の保存方式の変更は今回実装しない。
